# 🧑‍💻 Career Paths

The repository teaches a common engineering foundation first, then lets you specialize. Do not try to become a Kubernetes expert, cloud architect, SRE, security engineer and platform engineer simultaneously. That is a fine way to become excellent at browser tabs.

## Common foundation

All paths benefit from:

```text
Linux → Networking → Git → Scripting → DevOps → Containers → Cloud → IaC
```

Then specialize based on the role you want.

| Path | Core specialization |
|---|---|
| [Cloud Engineer](./cloud-engineer.md) | Cloud infrastructure, networking, IAM, automation |
| [DevOps Engineer](./devops-engineer.md) | CI/CD, IaC, containers, cloud, reliability |
| [DevSecOps Engineer](./devsecops-engineer.md) | Secure software delivery and supply chain |
| [Cloud Security Engineer](./cloud-security-engineer.md) | AWS security, identity, detection and Kubernetes security |
| [SRE](./sre.md) | Reliability, observability, SLOs and incident response |
| [Platform Engineer](./platform-engineer.md) | Developer platforms, golden paths and governance |

## How to use a career path

Each path is divided into:

- **Foundation:** concepts you should understand.
- **Core:** technologies you should be able to use.
- **Advanced:** skills that differentiate experienced engineers.
- **Projects:** evidence you can show in a portfolio.
- **Interview focus:** areas commonly tested in technical and scenario interviews.

Start with one path as your primary direction. Add adjacent skills after the core is strong.
