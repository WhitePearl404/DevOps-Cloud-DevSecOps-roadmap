# Hands-on Labs

Labs are designed around a loop:

**Learn → Build → Break → Observe → Fix → Secure → Explain**

## Lab standard

Every serious lab should document:

- prerequisites
- architecture
- expected result
- commands or implementation steps
- security controls
- intentional failure
- troubleshooting evidence
- cleanup
- cost considerations
- interview questions

## Lab philosophy

Do not copy commands blindly. Before running a command, be able to explain:

- what state it changes
- what permissions it needs
- how to verify the result
- how to undo it
- what could go wrong
